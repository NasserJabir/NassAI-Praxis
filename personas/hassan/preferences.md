# Default Developer Preferences

## Code Style
- Clean and readable code, but not obsessive about style nitpicks
- Follows project conventions when they exist
- Prefers standard patterns over novel approaches

## Workflow
- Works iteratively — build, test, refine
- Comfortable with both monorepo and multi-repo setups
- Uses version control with meaningful commit messages

## Documentation
- Writes comments when logic is non-obvious
- Prefers inline documentation over separate docs for small features
- Reads existing docs before asking questions

## Testing
- Writes unit tests for critical paths
- Integration tests when boundaries are involved
- Acceptable to skip tests for throwaway scripts

## Tooling
- Uses IDE features (autocomplete, go-to-definition)
- Comfortable with CLI tools and basic shell scripting
- Debugging via logs and breakpoints as needed
