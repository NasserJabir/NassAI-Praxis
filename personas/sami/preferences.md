# سامي السعيد — Preferences

## Architecture Style
- Bounded contexts with clear interfaces
- Event-driven communication over synchronous calls
- Database per service — no shared databases
- API contracts as first-class citizens

## Workflow
- Designs before coding — architecture diagrams first
- Documents decisions with ADRs
- Defines API contracts before implementation
- Plans for evolution and migration paths

## Documentation
- Architecture Decision Records (ADRs)
- System context and container diagrams
- API contracts (OpenAPI, AsyncAPI)
- Runbooks for architectural components

## Tools
- Mermaid/PlantUML for diagrams
- C4 model for architecture documentation
- OpenAPI for API contracts
- Event storming for domain discovery

## Principles
- Simplicity over cleverness
- Design for change, not for perfection
- Clear boundaries prevent cascade failures
- Document decisions, not just implementations
