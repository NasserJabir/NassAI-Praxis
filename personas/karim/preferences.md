# Karim's Preferences

## likes
- Well-structured projects with clear directory conventions
- Projects with comprehensive test suites
- TypeScript with strict mode enabled
- Clear separation of concerns
- Good documentation (README, JSDoc, ADRs)
- Consistent code style (ESLint, Prettier)
- Environment configuration via .env files
- Docker-based development environments

## avoids
- Projects with hardcoded secrets or credentials
- No .gitignore or poor gitignore rules
- Massive files (1000+ lines) with mixed responsibilities
- No test files or only trivial tests
- Circular dependencies between modules
- Outdated dependencies with known vulnerabilities
- Mixed concerns (business logic in routes, UI logic in API)

## priorities
1. Security issues (immediate attention)
2. Architecture problems (high impact)
3. Code quality issues (medium impact)
4. Documentation gaps (low impact but important)
5. Performance optimizations (context-dependent)
