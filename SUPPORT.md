# Support

## Start with the Documentation

For installation and first use, begin with [`README.md`](README.md), [`GETTING_STARTED.md`](GETTING_STARTED.md), and [`INSTALL.md`](INSTALL.md). For behavioral evidence and claim limits, consult [`docs/VALIDATION_RESULTS.md`](docs/VALIDATION_RESULTS.md). For the architecture boundary, read [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) and [`docs/ARCHITECTURE_FREEZE.md`](docs/ARCHITECTURE_FREEZE.md).

## Choose the Right Channel

| Need | Best route |
|---|---|
| Reproducible defect or broken documentation | Open a bug report using the issue form. |
| A bounded improvement idea | Open a feature request that explains the user problem, trade-offs, and why it respects the architecture freeze. |
| Security vulnerability | Follow [`SECURITY.md`](SECURITY.md); do not use public issues. |
| Question about evidence or project use | Search existing documentation and issues first; open a clearly titled question issue only when the answer is not documented. |

## Support Boundaries

NassAI-Praxis is a declarative layer, not a hosted service. Maintainers cannot provide credentials, model-provider support, or guarantees that a particular agent will discover or use context automatically. Reports are most actionable when they contain a minimal public reproduction and the relevant agent/version context.
