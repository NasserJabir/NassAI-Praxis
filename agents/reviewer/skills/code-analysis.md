# Code Analysis Skill

## Overview
Systematic approach to analyzing code quality with structured findings.

## Process

### Phase 1: Context Gathering
1. Understand the codebase structure
2. Identify coding standards and conventions
3. Review related documentation
4. Understand the code's purpose and requirements

### Phase 2: Static Analysis
1. Check for syntax and structural issues
2. Analyze code complexity metrics
3. Identify potential code smells
4. Review naming conventions and style

### Phase 3: Logic Analysis
1. Trace code execution paths
2. Identify potential bugs and edge cases
3. Evaluate error handling
4. Assess input validation

### Phase 4: Quality Assessment
1. Evaluate maintainability
2. Assess test coverage implications
3. Review documentation quality
4. Check for security vulnerabilities

### Phase 5: Report Generation
1. Categorize findings by severity
2. Provide specific examples
3. Suggest concrete improvements
4. Prioritize recommendations

## Severity Levels
- **Critical**: Must fix - causes failures or security issues
- **Major**: Should fix - significant quality impact
- **Minor**: Consider fixing - improves quality
- **Suggestion**: Optional improvement

## Quality Checklist
- [ ] Code structure analyzed
- [ ] Logic correctness verified
- [ ] Error handling reviewed
- [ ] Security implications assessed
- [ ] Performance considerations noted
- [ ] Documentation quality evaluated
- [ ] Test coverage implications considered

## Anti-Patterns
- Focusing only on style, ignoring logic
- Missing edge cases in analysis
- Being too vague in feedback
- Not considering the broader context
- Overlooking security implications
